Saarthi.AI System Architecture

AI-powered personalized learning platform · high-level request and data flow

Frontend Backend + Agentic AI Data User · LLMs · External APIs

Request flow

  • Browser → FastAPI (POST /learning/session) → services dispatch the CrewAI workflow.
  • Agents run in order: intent → planner → progress → feedback → nudge, each returning a Pydantic model.
  • JSON responses flow back up to the React workspace.

LLM fallback

  • Gemini keys 1–4 are primary with sticky rotation on quota and server errors.
  • Groq keys 1–3 engage only after Gemini is exhausted (backend/core/llm.py).
  • Structured outputs are preserved on both providers.

Data & external APIs

  • PostgreSQL persists sessions via SQLAlchemy; Redis is configured for cache.
  • The frontend fetches YouTube tutorials directly; the backend schedules Google Calendar events.

Browser capabilities

  • Mock interviews use the Web Speech API: recognition for answers, synthesis for speech output.
